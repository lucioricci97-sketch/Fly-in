Dijkstra, step by step

Click "Next step" to watch Dijkstra find the shortest path from S to E. The heap, distance table, and predecessor table all update in real time — exactly like in src/pathfinder.py.

What you just saw

  • Yellow nodes are in the heap, waiting to be processed.
  • Blue is the node currently being visited.
  • Green means we've settled the shortest distance to that node.
  • The distance table stores the best-known cost from S to each node.
  • The predecessor table remembers how we got there, so we can rebuild the path at the end.
  • When E is popped from the heap, we're done — its distance is final.

How this maps to pathfinder.py

while heap:
    d, node = heapq.heappop(heap)        # grey -> blue: pop smallest
    if d > dist.get(node, float("inf")):  # stale entry? skip
        continue
    if node == end:                      # found target -> done
        break
    for neighbour in self.graph.neighbours(node):
        edge_cost = self._edge_cost(neighbour, used_edges, node)
        if edge_cost is None: continue  # blocked
        nd = d + edge_cost
        if nd < dist.get(neighbour, float("inf")):
            dist[neighbour] = nd          # update distance table
            prev[neighbour] = node        # update predecessor
            heapq.heappush(heap, (nd, neighbour))

What to notice

  • Turns 1–2: drones flow into the pipeline two at a time because start→loop_a has max_link_capacity=2 and loop_a/loop_b both hold 2 drones.
  • Turn 3+: D1 enters the restricted connection to exit_point. It's drawn at the midpoint of the link (in-flight). Notice the connection blocks the rest until D1 arrives.
  • Every 2 turns one drone arrives at goal from this point: D1 turn 5, D2 turn 7, D3 turn 9, D4 turn 11, D5 turn 13, D6 turn 15. This is the bottleneck rhythm of the restricted zone.
  • Drones don't move twice in one turn — when a drone arrives from transit, it sits at exit_point for one turn before moving to goal. That's the one-action-per-turn rule.

How this connects to simulator.py

Each turn has two phases:

  1. _complete_transits() — in-flight drones arrive, the connection is freed, the drone is added to just_arrived so it skips phase 2.
  2. _advance_ready_drones() — every other drone tries one step forward, sorted by descending path_index so leading drones free space behind them.

Cheat sheet

One screen. Memorize this.

Project in three sentences

  1. Read a text map, build a graph of zones and connections.
  2. Plan paths with Dijkstra (heap-based, not networkx) and route drones along them.
  3. Simulate turn by turn, enforcing zone capacity, link capacity, blocked/restricted zones, and the 2-turn restricted-zone transit.

Zone types

TypeCostNotes
normal1Default. 1 turn to enter.
priority1Same cost, but preferred in pathfinding (-0.01 bonus).
restricted21 turn in flight, 1 turn arriving. Drone occupies the connection across both turns.
blocked∞Cannot be entered. Pathfinder skips entirely.

Capacities

  • Zone: max_drones (default 1). Start and end are unlimited.
  • Connection: max_link_capacity (default 1).
  • "Drones leaving free up the slot in the same turn" → we sort by descending path_index so leading drones move first.

Reflexes

  • "Why heapq?" → "Standard-library heap data structure. The subject forbids graph libraries, not data structures."
  • "Why Dijkstra over BFS?" → "Weighted edges (restricted = 2). BFS only works for unit weights."
  • "Why equal-cost alternates?" → "Longer detours delay drones without freeing the bottleneck. Verified empirically on circular_loop."
  • "How does restricted transit work?" → "1 turn in flight on the connection; arrival is the action for the next turn; drone cannot move again that arrival turn."
  • "What is zone_load?" → "Persistent count of drones currently in / reserved for each zone. Includes in-transit drones because their destination is reserved."
  • "What is link_load vs turn_link_use?" → "link_load persists across turns and only tracks in-flight restricted-transit drones. turn_link_use is a per-turn copy used for capacity checks during the move phase."
